# Flamer backend (Python)

A FastAPI + PostgreSQL implementation of the Flamer crawl-operations API. It is a drop-in replacement for the
TypeScript backend in `src/server`: same routes under `/api`, same JSON, same status codes and error messages. The
React UI runs against it unchanged.

The simulation is a pure function of `(run spec, operator actions, time)`. `flamer/sim` ports the TypeScript engine
with JavaScript number semantics (`Math.imul`, `>>> 0`, `Math.round`, left-to-right float sums, stable sorts), so its
output is identical to the TypeScript engine's. `tests/test_conformance.py` checks this against
`../fixtures/golden.json` with exact equality, including int-vs-float typing.

## Layout

```
flamer/
  contract.py            Pydantic models for the JSON contract (camelCase aliases)
  catalog.py geo.py      labels, blocker remedies, organisation and location lookup
  domains.py urlhost.py  domain-list cleaning (WHATWG URL host parsing, as in Node)
  js.py                  JavaScript number, string and date semantics
  sim/                   rng, domain profiles, engine
  aggregate.py graph.py seed.py
  app.py sse.py exports.py clock.py main.py
  store/                 Store protocol, in-memory store, PostgreSQL store (SQLAlchemy Core, asyncpg)
migrations/              Alembic (async env, autogenerated revision)
tests/
```

## Develop

```sh
uv sync --locked
uv run ruff check
uv run ruff format --check
uv run mypy
uv run pytest
```

PostgreSQL tests (the store contract plus the whole API suite against Postgres) run when `TEST_DATABASE_URL` is set,
and are skipped otherwise. The suite migrates that database to `head` and back to `base`:

```sh
TEST_DATABASE_URL=postgresql+asyncpg://flamer:flamer@localhost:5432/flamer uv run pytest
```

Run the API locally (in-memory store, demo data seeded on first request):

```sh
uv run uvicorn flamer.main:app --reload --port 8000
```

Use PostgreSQL by setting `DATABASE_URL` and migrating first:

```sh
export DATABASE_URL=postgresql+asyncpg://flamer:flamer@localhost:5432/flamer
uv run alembic upgrade head
uv run uvicorn flamer.main:app --port 8000
```

After changing `flamer/store/schema.py`, generate a migration with
`uv run alembic revision --autogenerate -m "..."`. A post-write hook runs ruff on it.

## Configuration

| Variable           | Default     | Meaning                                                                 |
| ------------------ | ----------- | ----------------------------------------------------------------------- |
| `DATABASE_URL`     | unset       | PostgreSQL URL (`postgresql://` or `postgresql+asyncpg://`). Unset or empty: in-memory store. |
| `STATIC_DIR`       | `/app/dist` | Built SPA. Served with an `index.html` fallback when the directory exists. |
| `FLAMER_SANDBOXES` | on          | `off` ignores the `x-flamer-sandbox` header, so everyone shares one dataset. |

## Docker

Build from the repository root. The first stage builds the SPA with the committed Yarn release, the second installs
the locked Python dependencies with uv, and the final image runs as a non-root user on port 8000:

```sh
docker build -f backend-python/Dockerfile -t flamer-python .
docker run --rm -p 8000:8000 -e DATABASE_URL=postgresql+asyncpg://flamer:flamer@postgres:5432/flamer flamer-python
```

On start the container runs `alembic upgrade head` (only when `DATABASE_URL` is set), then `uvicorn`.
`backend-python/Dockerfile.dockerignore` takes the place of the root `.dockerignore` for this build.

## Storage

- `namespaces`: one row per dataset (`shared` or a visitor sandbox), with the `seeded_at` claim and the demo `clock` (JSONB).
- `runs`: `(namespace, id)` primary key, `created_at`, the run `spec` as JSONB. Deleting a namespace cascades.
- `run_actions`: append-only, ordered by an identity column, with `(namespace, run_id, action_id)` unique and a foreign
  key to `runs`.

Seeding is idempotent across processes: `seed_once` claims the namespace row with
`INSERT … ON CONFLICT DO UPDATE … WHERE seeded_at IS NULL RETURNING` and inserts the demo runs in the same transaction.
